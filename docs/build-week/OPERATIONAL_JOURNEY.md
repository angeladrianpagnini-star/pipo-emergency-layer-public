# Operational Journey

## Purpose

The primary Build Week experience presents the PIPO operational journey in less than one minute. It keeps the deeper
architecture available as a secondary, collapsible view while making the end-to-end incident cycle visible first.

## Demonstration scenario

The fictional scenario is a road incident with an injured person, a possible spill, fire risk, and disrupted traffic.
It routes simulated context in parallel to the PIPO Master Console, 911 Security, 107 Health, Traffic, and Fire
response. The region selector can replace those names with generic international demonstration labels.

## Eight guided stages

1. Citizen activation.
2. Master reception.
3. Parallel routing.
4. Resource assignment.
5. Field intervention.
6. Documentation.
7. Institutional closure.
8. Citizen return.

The previous-step control only changes focus. It does not delete previously appended demonstration events. Restart
creates a new in-memory demonstration run.

## Safety and ownership

All devices, location, media, organizations, people, distances, and times are fictional. No real sensor, location,
media, dispatch, tracking, or emergency-service integration is used. Each agency card has a separate resource,
operator, state, and individual intervention record. The master console integrates references without rewriting the
source records: integration without documentary absorption.

## Demonstration ledger

The journey emits linked in-memory events for master reception, routing, resource selection and assignment, field
status, documentation, closure, and citizen package delivery. The visible ledger shows each event reference and its
previous reference. It is not an official evidentiary chain of custody.
